# Chekki AI - Platform Sync Notes

This document captures important steps for maintaining consistency between the web codebase and the native Android/iOS platforms following the recent refactor.

### 1. Versioning

We have centralized the application version in `src/version.ts`.

> [!IMPORTANT]
> **RELEASE CHECKLIST**: Before pushing a new build to the App Store:
>
> 1. Increment `version` in `package.json`.
> 2. Update `APP_VERSION` in `src/version.ts` (This controls the Splash Screen/UI version display).
> 3. Ensure `versionName` (Android) and `MARKETING_VERSION` (iOS) match.
> 4. Run `npm run mobile` to sync all assets.

- **Action**: Always update `src/version.ts` first.
- **Android Studio**: Ensure `versionName` in `app/build.gradle` matches `src/version.ts`.
- **Xcode**: Ensure `MARKETING_VERSION` in your project settings matches `src/version.ts`.

### 2. Build & Sync Pipeline

We have optimized the build scripts in `package.json`.

- **Action**: Use `npm run mobile` to build the app and sync it to your platforms.
- **What it does**:
  1. Runs `tsc` (Type check)
  2. Runs `vite build` (Bundles landing page and app)
  3. Swaps `index.html` (Landing) with `app.html` (App) for the distribution folder.
  4. Runs `npx cap sync` to update the native projects with the new assets.

### 3. Code Quality (ESLint/Prettier)

We added formal linting to prevent small bugs (like placeholder keys or version mismatches) from reaching production.

- **Action**: Run `npm run lint` before committing major changes.
- **Action**: Run `npm run format` to keep the code clean and consistent.
- **Note**: You may need to run `npm install` once to install the new dev dependencies (`eslint`, `prettier`).

### 4. Analysis Logic

The core analysis logic has been moved from `App.tsx` into a custom hook: `src/hooks/useWorksheetAnalysis.ts`.

- **Maintenance**: If you need to change how AI tokens are handled, how scan limits are checked, or how the `AbortController` behaves, look in this hook rather than the main `App.tsx`.
